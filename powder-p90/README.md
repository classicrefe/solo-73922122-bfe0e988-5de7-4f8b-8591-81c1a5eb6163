# 粉体粒径档表 · 多批合并 P90 最紧界核算

按批号上传粉体粒径**档表**（连续排列、互不重叠的整数微米闭区间），同批可补报
同一组粒子的不同分档表（入库前做整体相容性校验）；在网页勾选多批后，计算合并后
**P90 的最紧上下界**，并各给出一份能真实取到该端点的**逐批粒径频数见证**。
全程按档运算，不逐粒展开，合计 10 亿粒也按档秒级完成。

并发语义：同一批号的上传按批号串行化（文件锁，跨 gunicorn 进程与线程生效），
`查已有档表 → 整体相容性校验 → 写入` 是一个不可分割的整体。因此

- 两人同时给同一**新**批号首报：只建一个批次，两张相容的首报都归入该批；
- 两张补报各自与旧表相容、彼此冲突：只有先取得批号锁的一张入库，另一张整张
  退回并在页面提示冲突切割点；已入库档表不受影响，仍可用于核算；
- 不同批号使用不同锁文件，**某批校验尚未完成时其他批次照常入库**。

## 启动方式

### Docker Compose（推荐演示）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
# 另开终端灌入演示数据（容器内）：
docker compose exec web python -m scripts.seed
```

`docker-compose.yml` 固定保留 **2 个 gunicorn 工作进程**（`--workers 2`），
批号锁同样是跨进程的。SQLite 数据文件保存在命名卷 `powder-data`（容器内
`/app/data/powder.db`），批号锁文件在同目录 `locks/` 下，容器重建不丢数据；
健康检查命中 `GET /`。

### 本地 Python

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python -m scripts.seed            # 可选：写入演示三批
gunicorn -w 2 -b 0.0.0.1:8000 app.main:app
```

## 网页演示流程

> 演示“两人同时提交”时，可在浏览器开两个标签页，或用两条命令并发提交；
> 两个工作进程会分别处理，结果与单进程一致。

1. **首报（新批号）**：批号 `B-ALPHA`，粘贴（每行 `lo hi count`，空格或逗号分隔）：
   ```
   0 99 400
   100 199 500
   ```
   提示“新批 B-ALPHA 已创建”，该批只有 1 个批次。
2. **相容补报**：同批号再贴一张更细的分档表，提示“补报成功”，该批现有 2 张档表：
   ```
   0 49 100
   50 99 300
   100 149 400
   150 199 100
   ```
3. **不相容补报（被拒绝、不入库）**：同批号贴
   ```
   0 49 450
   50 99 0
   100 199 450
   ```
   页面给出冲突切割点与原因；批次详情里仍是原来的 2 张档表，后续核算只按
   已入库档表进行。
4. **并发冲突补报（演示批号锁）**：先给新批号 `B-RACE` 首报 `0 9 100 / 10 19 100`，
   再**同时**提交下面两张表。它们各自与旧表相容，但 `[0,4]` 一报 50 粒、一报 90 粒，
   彼此冲突；只有先入库的一张被收下，另一张提示“补报被拒绝…档表冲突”，库里
   始终只有 2 张表且仍能核算：
   ```
   0 4 50        0 4 90
   5 9 50        5 9 10
   10 19 100     10 19 100
   ```
5. **勾选批次 → 核算**：页面展示总粒数、k=⌈0.9N⌉、P90 最紧下界/上界，
   以及左右两份逐批粒径频数见证（每份都符合该批全部档表，合并后第 k 粒恰好
   等于对应端点）。

以上 ①–④ 也可用脚本一次跑完（服务启动后）：

```bash
python -m scripts.demo_web http://localhost:8000
```

脚本会打印每次上传的页面提示，并在第 ④ 步用两个线程同时提交冲突补报，
断言“收下 1 张、退回 1 张”。

## 算法要点（按档计算，不展开粒子）

对档表 T 记切割点 `cuts=[lo0, hi0+1, hi1+1, …]` 与档累计 `cum`。对任意整数
切割点 c，任一相容粒子组中“粒径 < c 的粒数”被夹在：

- `S_T(c)`：完全位于 c 左侧（`hi+1 ≤ c`）的档粒数和（下界）；
- `E_T(c)`：档起点 `lo < c` 的档粒数和（上界）。

一批所有档表的切割点取并集，该批的累计走廊为逐点
`L(j)=max_T S_T(c_j)`、`U(j)=min_T E_T(c_j)`。**多表相容 ⇔ 总粒数一致且
处处 L(j) ≤ U(j)**（在表自身切割点上 S=E，CDF 被钉死，走廊宽度只出现在档内）。

多批各批独立，合并走廊为各批 L/U 之和。设 `k=⌈0.9N⌉`：

- 最紧**下界** = 首个满足 `U(j+1) ≥ k` 的原子段 `[c_j,c_{j+1})` 的左端点；
- 最紧**上界** = 首个满足 `L(j+1) ≥ k` 的段的右端点 `c_{j+1}-1`。

见证（每批一份，合并后第 k 粒恰为端点）：

- 下界见证：段 j 放 `U(j+1)-U(j)` 粒、堆段左端（CDF 处处贴 U）；
- 上界见证：段 j 放 `L(j+1)-L(j)` 粒、堆段右端（CDF 处处贴 L）。

所有 S/E 序列由双指针线性归并得到，复杂度 O(表数 × (档数 + 全局切割点数))，
空间与档数同阶，与粒数无关。

## 自测

```bash
python -m unittest discover -s tests -v
```

- 解析/校验、S/E 走廊、相容性（含总粒数不一致、分档冲突、零粒尾档扩展）；
- 300 组随机模糊：先造具体粒子组再生成不同分档，产品结果与逐整数暴力参考
  实现完全一致，见证逐点贴住 L/U 且原始真实粒子组的 P90 落在界内；
- 200 组随机不相容档表，产品判定与暴力判定一致；
- 10 亿粒按档核算、2 万档线性时间（秒级）、见证规模与档数同阶；
- 并发上传：同批首报只建一个批次且无 500；冲突补报只收一张；
  慢批校验未完成时其他批次的补报不受阻塞（文件锁按批号隔离）。

## 约束与语义

- 档：非负整数 `lo ≤ hi`，档间首尾相接、互不重叠；粒数非负，整表至少一粒；
- 允许零粒档；允许补报表用零粒尾档把覆盖范围往外扩（不要求新粒子）；
- 同批各表总粒数必须相同；每张表入库时都须与当时库内该批**全部**档表相容；
  冲突时整张退回、不写库，已入库档表不受影响、仍可用于核算。
